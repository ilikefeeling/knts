# Field-Master (knts) 보안 아키텍처 및 업무 배정 명세서

## 1. 개요
본 문서는 Field-Master 시스템의 보안 아키텍처(E2EE)와 핵심 기능인 **[보조원 업무 배정 시스템]**의 고도화된 프로토콜 규칙을 명시합니다. 시스템의 모든 개발, 유지보수, 운영은 본 명세서의 불변의 원칙을 준수해야 합니다.

---

## 2. 보안 아키텍처 (E2EE: End-to-End Encryption)

Field-Master는 대상자의 민감한 개인정보(성명, 상세주소 등)를 보호하기 위해 **종단간 암호화(E2EE)**를 설계의 근간으로 삼습니다.

* **마스터 PIN 기반 암호화:** 관리자가 설정한 6자리 PIN은 데이터베이스에 해시 형태로만 저장되며, 실제 암/복호화 키로 사용되는 평문 PIN은 서버에 절대 전송되거나 저장되지 않습니다.
* **클라이언트 사이드 암호화:** 모든 민감 데이터는 사용자의 브라우저(관리자 PC 또는 보조원 모바일 기기)에서 PIN을 통해 복호화됩니다.
* **영지식(Zero-Knowledge) 원칙:** 데이터베이스가 해킹당하더라도, PIN을 모르는 공격자는 저장된 데이터를 해독할 수 없습니다. 관리자 및 보조원은 절대로 PIN을 분실하거나 외부로 유출해서는 안 됩니다.

---

## 3. 보조원 업무 배정 시스템 원칙 (고도화 제안 반영)

보조원에게 업무를 배정하는 과정은 현장 실무의 무결성을 보장하기 위해 다음의 **엄격한 상호 검증 및 원칙 준수 프로토콜**을 따릅니다.

### 3.1. 불변의 제약 규칙 (Rule Enforcement)
1. **상태 기반 배정 잠금 (State Lock):**
   * 상태가 `[방문 완료]` 또는 `[진행 중]`으로 변경된 업무는 일반적인 자동 배정이나 일괄 배정을 통해 타인에게 덮어씌워질 수 없습니다.
   * 부득이한 재배정은 관리자의 명시적인 '배정 강제 회수' 절차를 통해서만 가능합니다.
2. **최대 보유량 (CAP) 제한:**
   * 한 보조원에게 과도한 업무가 몰리는 것을 방지하기 위해 시스템/계정별 설정된 '미완료 업무 최대 개수'를 초과하여 배정할 수 없습니다.
3. **작업자 유효성 검증:**
   * 삭제 처리되거나 비활성화된 보조원에게는 DB 트리거 및 어플리케이션 로직 레벨에서 배정이 원천 차단됩니다. (ON DELETE SET NULL 및 상태 교정 적용)

### 3.2. 2-Step 상호 검증 배정 (Maker-Checker Process)
대량의 업무를 한 번의 실수로 잘못 배정하는 휴먼 에러를 방지하기 위해 **[프리뷰 -> 최종 승인]** 프로세스를 강제합니다.

* **[Step 1] 배정 시뮬레이션 및 아웃라이어 분리:**
  * 배정 실행 시 즉시 DB에 반영되지 않으며, 화면에 **'배정 예정 리포트(Preview)'**를 출력합니다.
  * **(중요) 별도 목록 분리 기능:** 주소가 부정확하거나, 기존 미방문 누적이 비정상적으로 많은 대상자 등 '평균을 벗어나는 대상자(Outliers)'는 자동 균등 배정 대상에서 제외되어 **별도 목록**으로 분리됩니다. 이들은 관리자가 직접 검토 후 개별 배정해야 합니다.
* **[Step 2] 최종 배정 승인:**
  * 관리자가 시뮬레이션 결과와 아웃라이어 명단을 확인한 후, 명시적으로 `[최종 배정 승인]`을 누를 때만 원자적 트랜잭션(All or Nothing)을 통해 일괄 배정됩니다.

### 3.3. 보조원 수락(Handshake) 기반 소유권 이전 (Phase 2 도입 예정)
운영 데이터 분석을 거친 후 추후 도입될 강력한 상호 승인 기능입니다.
* 관리자가 배정을 완료하더라도 상태는 `[수락 대기]`가 됩니다.
* 현장 보조원이 앱에서 자신의 업무 내용을 확인하고 `[업무 수락]`을 눌러야만 비로소 해당 보조원의 책임 하에 업무가 확정됩니다. (일정 시간 미수락 시 자동 회수)

### 3.4. 불변의 이력 기록 (Immutable Audit Trail)
* 업무 배정, 회수, 변경 등 소유권이 변동되는 모든 이벤트는 타임스탬프와 함께 `assignment_logs` 등 감사(Audit) 기록으로 영구 저장됩니다.
* 분쟁 발생 시, 배정 시점과 수락 시점 등을 명확히 증명하는 근거 자료로 활용됩니다.
