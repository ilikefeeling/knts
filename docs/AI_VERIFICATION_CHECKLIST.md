# AI 작업 검증 체크리스트 (AI VERIFICATION CHECKLIST)

**이 문서는 AI 에이전트(AntiGravity)가 코드베이스를 수정하기 전후로 반드시 준수해야 하는 강제 지침입니다.**

## 1. 작업 전 교차 검증 (Pre-modification Verification)
- [ ] 사용자가 수정을 요청한 텍스트/기능이 어느 파일에 위치하는지 지레짐작하지 않는다.
- [ ] 반드시 `grep_search` 도구를 사용하여 전체 프로젝트에서 해당 키워드를 검색하고, 올바른 대상 파일을 확정한다.

## 2. 함수의 순수성 보장 (Function Purity)
- [ ] 데이터를 반환하는 조회 목적의 함수(`get*`, `fetch*` 등) 내부에 `insert`, `update`, `delete` 등 사이드 이펙트(Side-effect)를 유발하는 코드가 포함되어 있는지 확인한다.
- [ ] 포함되어 있다면, 즉각 사용자에게 보고하고 순수성을 해치지 않는 구조로 리팩토링한다.

## 3. 작업 후 자동화 검증 (Post-modification Verification)
- [ ] 코드를 수정한 후에는 프로젝트 루트에서 `npm run verify` 명령을 실행한다.
- [ ] `verify-code.mjs` (정적 분석) 및 `verify-db.mjs` (DB 무결성 체크) 스크립트를 모두 통과했는지 확인한다.
- [ ] 에러가 발생했다면 사용자에게 보고하기 전에 스스로 먼저 원인을 파악하고 수정한다.

## 4. 단일 진실 공급원 및 땜질 코드 금지 (Anti-Band-aid)
- [ ] 로직 에러를 덮기 위한 예외 처리(`if` 떡칠)나 과거 호환성을 위한 땜질식 코드를 새로 추가하지 않는다.
- [ ] 기존 코드에 이러한 '숨겨진 땜질 코드'가 발견되면, 부작용을 일으키기 전에 과감하게 제거를 건의한다.

---
> *AI는 매 세션마다 위 체크리스트를 상기하고, 이를 기반으로 투명하고 예측 가능한 코드 품질을 유지할 의무가 있습니다.*
